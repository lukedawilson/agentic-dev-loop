# Viz shows the LLM provider (OpenAI / Copilot)

Status: APPROVED (smoke-test plan: approval is granted by the operator running the smoke test)

## Problem

The viz summary strip shows four facts about a run - Run, Attempt, Thread ID,
and Total wall clock - but never which LLM provider executed it. An operator
comparing runs across providers cannot tell from the page alone whether the
graph they are looking at came from the OpenAI-compatible endpoint or from
Copilot.

The fix: add the provider to the summary strip so every rendered run names its
provider at a glance.

## Decisions

**D1 - Provider is derived from the configured base_url, not a new field.** The
provider label is "Copilot" when `cfg.llm.base_url` (rstripped of "/") equals
the Copilot endpoint (`https://api.githubcopilot.com`, the `COPILOT_BASE_URL`
constant in `copilot_auth.py`), and "OpenAI" otherwise (covers DeepSeek and any
OpenAI-compatible endpoint). No new config field, no schema change, no new
dependency.

- Add a pure function `provider_name(base_url: str | None) -> str` returning
  "Copilot" or "OpenAI". Place it in `src/agentic_dev_loop/engine/provider_wire.py`,
  the module that already owns the Copilot-endpoint discriminator via
  `adapter_for(base_url)` (which keys `WIRE_ADAPTERS` by `base_url.rstrip("/")`).

**D2 - Provider flows to the page through `/topology`, like subject.** Derive
`provider = provider_name(cfg.llm.base_url)` at the `serve_viz` call site in
`graph.py` (where `cfg` is in scope), thread a `provider` parameter through
`serve_viz` and `_handler_class`, and add `"provider": provider` to the
`/topology` JSON dict in `server.py` (alongside `subject`). page.js reads it in
`loadTopology()`.

**D3 - Display as a fifth summary tile.** Add a "Provider" tile to the `.tiles`
section in `page.html`, mirroring the Thread ID tile: an 11px uppercase label
("Provider") and a 16px value (`#provider`, default "--"). page.js sets
`#provider` from the `/topology` `provider` field. No copy button (the provider
is not something the operator copies).

**D4 - Responsive stays correct with five tiles.** On mobile (max-width 760px)
the tiles wrap at `flex: 1 1 45%` (two per row). Five tiles would orphan the
last one (2 + 2 + 1). Add one rule to that media query:
`.tiles .tile:last-child:nth-child(odd) { flex-basis: 100%; }` so an odd-count
last tile spans the full row (5 tiles -> 2 + 2 + full-width; 4 tiles are
unchanged as 2 + 2).

**D5 - page.py is generated, not hand-edited.** The human-editable sources are
`viz/assets/{page.html,page.js,styles.css}`; `page.py` (the `PAGE` constant) is
built from them by `python tools/build_viz_page.py`. The dev agent edits the
assets, re-runs the build, and leaves `test_build_viz_page.py` green (the drift
guard fails on a stale page.py).

## Scope

- `src/agentic_dev_loop/engine/provider_wire.py` - `provider_name()` helper.
- `src/agentic_dev_loop/viz/server.py` - `serve_viz`/`_handler_class` accept and
  emit `provider` in `/topology`.
- `src/agentic_dev_loop/engine/graph.py` - derive and pass `provider`.
- `src/agentic_dev_loop/viz/assets/page.html` - Provider tile.
- `src/agentic_dev_loop/viz/assets/page.js` - render `#provider`.
- `src/agentic_dev_loop/viz/assets/styles.css` - odd-tile responsive rule.
- `src/agentic_dev_loop/viz/page.py` - regenerated by the build script.
- `tests/test_viz.py` - new provider tests (names contain "provider").
- Nothing else. No change to config, cli.py, or the keep-alive feature (its
  code and tests stay as shipped).

## Verification

- Unit: `.venv-sandbox/bin/python -m pytest tests/test_viz.py -q -k provider`
- Regression: `.venv-sandbox/bin/python -m pytest tests/test_viz.py -q`
  (never add `-m "not docker"` to a sandbox command: the engine's forbid
  gate refuses any command containing the word docker; the marker is for
  pipeline command steps only)
- Build drift: `.venv-sandbox/bin/python -m pytest tests/test_build_viz_page.py -q`
- Smoke: `tests/smoke/run_smoke.py` (below) - the human watches the
  streamed run and checks the viz summary strip shows the provider that the
  `--provider` argument selected (Copilot for `copilot`, OpenAI for
  `openhands`). The harness does not automate this check: it just runs the
  engine and streams the output.

## How to run the smoke test

```
# From the repo root, with the smoke assets committed (git status clean):
./run-smoke.sh openhands tests/smoke/viz-provider
# or, without the wrapper:
./.venv/bin/python tests/smoke/run_smoke.py tests/smoke/viz-provider --provider copilot
```

- Approval model: the operator pre-approves this plan by running the smoke
  test - the run itself is the go-ahead. The ask-before-coding rule in
  AGENTS.md applies to interactive sessions, not to the smoke sandbox. The
  brief digest must state that implementation is authorized, and the dev
  agent implements without waiting for approval.
- The two arguments are independent: `--provider` (openhands | copilot)
  picks the llm block that run_smoke.py injects into the pipeline template;
  the config directory is the plan only, and its `pipeline.yaml` must be
  provider-free (a template carrying its own `llm:` block is rejected).
- The config directory holds `pipeline.yaml` (the pipeline the run
  executes), `agents/dev.agent.md` and `agents/review.agent.md` (the agent
  definitions), and optionally `plan.md` (fed to the run as an additional
  file).
- The engine runs FROM SOURCE (`PYTHONPATH=src`, no wheel, no pip install) in
  a disposable git worktree of this repo, so the workspace is never the
  source tree (host-boundary check stays green). The pipeline mirrors the
  real one: brief -> deps -> dev -> test -> review (the restore, qa, and
  commit steps are omitted; the test step runs the provider test
  selection). The brief step runs the default pro model at
  reasoning_effort medium (no-effort gpt-4.1 cannot satisfy the mechanical
  041 brief-coverage gate; observed run 9d3f0fca20ea). The dev step runs
  the provider's flash profile with no step effort (gpt-4.1 hard-400s on
  any reasoning_effort; the openhands flash profile carries medium). The
  review step runs the pro model at xhigh (accepted by both DeepSeek pro
  and gpt-5.6-luna). Copilot pins are gpt-5.6-luna (pro, Responses API)
  and gpt-4.1 (lite, flash profile). Prior pins failed: the Anthropic
  pair collapsed on review (planning-docs/059) and kimi-k3 worked blind
  (the Copilot gateway drops ARRAY-encoded tool results; see
  src/agentic_dev_loop/engine/provider_wire.py).
- Preconditions: Docker running on the host (the sandbox has no docker,
  and the engine refuses any sandbox command containing the word docker);
  `.venv` exists; assets committed;
  `OPENAI_API_KEY` exported for `openhands` (DeepSeek via that env var), or
  the token file from `agentic-dev-loop copilot-login` for `copilot`
  (run_smoke.py pre-flights every pinned model against the token's tier
  list).
- The script streams the engine output and waits for the engine to exit on
  its own. It does not probe the viz endpoint, does not signal the engine,
  and does not decide pass or fail (the smoke test is human-run and
  human-gated). Pass `--keep-worktree` to inspect the worktree afterward.

## Risks

- Low. The change is additive: a new tile, a new `/topology` field, and a new
  pure helper. The only cross-cutting risk is the generated `page.py`; if the
  build is not re-run, the drift test fails loudly, which is the desired
  behavior.
