# Business Rules - Unit 13 (Reporting Viz Extension)

Numbered rules the implementation must honor. Rules trace to the intent doc (FR-13.1..13.8), the FD decisions (FD-Q1..Q4), and the unit-12 module behavior.

## Endpoints and transport

- BR-1 GET ONLY. The new routes accept GET exclusively; any other method returns 405 with an Allow header. Existing routes keep their behavior.
- BR-2 ROUTES. /runs -> RunsPage HTML; /runs/<id> -> RunDetailPage HTML (same shell, client reads pathname); /runs/data -> RunsListPayload JSON; /runs/<id>/data -> RunDetailPayload JSON. Routes are active in BOTH pipeline mode (live run serving) and history mode (FD-Q1 A).
- BR-3 PER-REQUEST COMPUTATION. Every /runs/data and /runs/<id>/data call recomputes from reporting.sources/metrics (live read, no caching, no timers) (FD-Q2 answer).
- BR-4 JSON SHAPE. Metrics serialize via Metric.as_dict() only; run records serialize via an explicit to-dict function (no raw dataclass dumps); timestamps ISO; JSON emitted with ensure_ascii=True (ASCII-only, repo rule).
- BR-5 FILTER PARAMS. /runs/data accepts since (ISO datetime), until (ISO datetime), status (comma-separated values from STATUS_VALUES). Semantics mirror unit-12 apply_filters (since inclusive, until exclusive, applied to ts_start). Invalid values -> 400 with a JSON error body. Pipeline/workspace filters are NOT accepted (deferred).
- BR-6 UNKNOWN RUN. /runs/<id>/data for a missing run dir -> 404 JSON. The detail page renders its not-found state client-side.

## Data and degradation

- BR-7 SINGLE SOURCE OF TRUTH. All data comes from unit-12 reporting.sources (discover, read_audit, read_dir, build_run_records) and reporting.metrics (pure_metrics, apply_filters). The viz layer performs NO metric computation of its own (FR-13.2).
- BR-8 DEGRADATION INHERITED. Unavailable metrics carry availability + reason into the JSON; the UI renders them with the unavailable style, never fabricates (FR-13.8, unit-12 BR-13).
- BR-9 READ-ONLY. The viz routes only ever read; sqlite opens stay immutable (unit-12 sources behavior). No writes, no new files, no cache dirs (unit-12 FR-12.8 applies).
- BR-10 SNAPSHOT SEMANTICS. During a live run, /runs reads are snapshots of the checkpoint store; the in-flight step may be absent from the latest thread. That is accepted (history view describes completed data); the UI labels live threads with the running status from the checkpoint state.

## View and styling

- BR-11 SKIN ONLY. Styling uses the unit-9 hand-written skin and CSS tokens; no new framework, no new dependency (FR-13.6). New assets follow viz/assets/ conventions; generated page.py files are produced by tools/build_viz_page.py and carry the "Generated by" header (never hand-edited).
- BR-12 PROVENANCE BADGES. Every rendered metric shows its provenance ([mechanical]/[parsed]/[claimed]) and unavailable metrics show their reason (FR-13.7).
- BR-13 REFRESH. The runs page refreshes on visibilitychange (tab switch) and via a manual refresh button; no polling timers (FD-Q2 modified answer).
- BR-14 HISTORY LINK. In pipeline mode the live page header gains a History link to /runs (FD-Q1 A). In history mode / serves the runs page directly.
- BR-15 CHARTING. Charts render with ECharts 6.1.0 common bundle (vendored, pinned SHA256 61f13280aba3161f77fc801bf5f9c786f55f10432153a0683fc5cc0700b013d5, Apache-2.0, SVG renderer). Theming via the getComputedStyle token bridge with full re-render on theme change; every instance gets an explicit resize handler (ECharts has no built-in resize observation); grid children need min-width: 0 (validated resize-deadlock fix); the aria option is a validated no-op for SVG, so the SVG text exposure IS the a11y story. EXTSRF: re-probe the pinned artifact before any version bump (HC-6). Selection record: planning-docs/unit-13-charting-selection.md.
- BR-16 ASCII. All committed assets, generated pages, and JSON are ASCII-only (repo test_repo_ascii.py + em-dash ban).

## Launcher and build

- BR-17 LAUNCHER. `python -m agentic_dev_loop.viz --history [--port N]` serves the runs view with no --pipeline required; --pipeline mode is unchanged except for the added /runs routes. Port fallback and loud --viz-port errors keep existing behavior.
- BR-18 BUILD PIPELINE. tools/build_viz_page.py is extended to emit both PAGE and RUNS_PAGE from viz/assets/*; the single-marker rule applies per template; a test asserts generated output equals the rebuilt output (drift guard).
