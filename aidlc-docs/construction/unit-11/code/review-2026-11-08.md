## Required changes

### M2 - Mechanical gate output must not be labeled as agent claims

- Evidence: src/agentic_dev_loop/engine/stages.py:463-467 folds all notes
  into "## Stage artifacts (each agent's own claims, not verified)".
  Command/action failure notes carry real process output
  ("## test output (attempt 1) ..." from make_command_node /
  make_action_node).
- Problem: that output is mechanically produced fact, not an agent claim.
  Teaching the dev agent to read failing test output as "unverified claims"
  weakens the gate's authority.
- Required: route mechanical command/action output into the verified
  channel (or a separate mechanical-notes section); only agent prose goes
  under claims. Pin with a test that a failing command step's output does
  not appear under the claims heading.

### M3 - Register the new import-time SDK monkeypatches in COMPAT-SHIMS.md

- Evidence: src/agentic_dev_loop/engine/llm.py:95-121 adds global patches
  _wire_checked_completion / _wire_checked_responses; COMPAT-SHIMS.md and
  tests/test_sdk_compat.py are unchanged (0-line diff).
- Required: registry entries per repo policy (removal criterion, target SDK
  version, pinning test) plus tests/test_sdk_compat.py pins; or move the
  validation to a non-monkeypatch seam.

## Minor changes (same pass)

### m4 - verified_state survives bumps

The bump node resets failure_class but not verified_state, so attempt 2's
context can present attempt 1's "test: exit 1" as a current verified fact
before re-verification. Tag facts with the attempt or clear on bump; pin
with a test.

### m5 - D-3 positional zip can silently under-check

src/agentic_dev_loop/engine/provider_wire.py:86 zips messages with the
serialized output positionally and assumes 1:1 alignment; a serializer that
drops or reorders messages would silently degrade the check. Add a
length/alignment assertion so the validator fails loudly.
